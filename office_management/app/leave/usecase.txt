Base URL: /leave/

All endpoints use POST.
API endpoint	                            Purpose	                                        Intended user
/leave/types/list/	                        List active leave types	                        Admin and Employee
/leave/types/create/	                    Create a leave type	                            Admin
/leave/types/update/	                    Update leave type details	                    Admin
/leave/types/deactivate/	                Deactivate a leave type	                        Admin
/leave/balances/my/	                        View own leave balances	                        Employee
/leave/balances/list/	                    View organization employee leave balances	    Admin
/leave/balances/initialize/	                Initialize yearly balances for employees	    Admin
/leave/balances/adjust/	                    Manually adjust an employee's leave allocation	Admin
/leave/applications/create/	                Apply for leave	                                Employee
/leave/applications/my/	                    View own leave applications	                    Employee
/leave/applications/list/	                View organization leave applications	        Admin
/leave/applications/review/	                Approve or reject an application	            Admin
/leave/applications/cancel/my/	            Cancel own application	                        Employee
/leave/applications/cancel/organization/	Cancel an employee's application	            Admin
/leave/transactions/list/	                View leave balance transaction history	        Admin

2. Leave balances

        Request:
        {
          "leave_year": 2026,
          "leave_type_id": 1

    2.3 Initialize leave balances
        Admin
        POST /leave/balances/initialize/

        Request:
        {
          "leave_year": 2026,
          "leave_type_ids": [1, 2]
        }

        leave_type_ids is optional. If omitted, all active leave types are initialized for all active employees.

        Response:
        {
          "status": true,
          "message": "Leave balances initialized successfully.",
          "data": {
            "created": 20,
            "existing": 5
          }
        }

    2.4 Adjust leave balance
        Admin
        POST /leave/balances/adjust/

        Request:
        {
          "balance_id": 10,
          "days": 2,
          "remarks": "Additional leave allocation"

        Use positive days to increase allocation and negative days to decrease it.

3. Leave applications

    3.1 Create leave application
        Employee
        POST /leave/applications/create/

        Request:
        {
          "leave_type_id": 1,
          "start_date": "2026-11-05",
          "end_date": "2026-11-06",
          "reason": "Personal work"
        }

        The backend calculates total_days using calendar and shift rules.

        Response:

          "status": true,
          "message": "Leave application submitted successfully.",

            "employee": 15,

    3.6 Organization cancel application
        Admin
        POST /leave/applications/cancel/organization/

        Request:
        {
          "application_id": 101
        }

        Response: Same complete application response as employee cancellation, with status: "CANCELLED".
        This supports:
        - Cancelling a pending application: releases pending balance.
        - Cancelling an approved application: restores used balance and resets its ON_LEAVE attendance records to INCOMPLETE.

Note on LWF: LWF is actually a fixed amount (e.g. ₹25 employee + ₹75 employer in Maharashtra for 2024), not a percentage. But your StatutoryRateConfig model requires a percentage. For v1, either:

Use these percentage approximations, or

Set rate_percentage: "0.0000" and treat LWF as zero until you extend the model to support fixed-amount rate configs.

If you don't need LWF yet, skip 1.7 and 1.8 — leave is_lwf_applicable=false for all orgs for now.


Step 2 — Create Maharashtra PT slabs (state_id = 19)
Maharashtra PT is monthly, slab-based, with a ₹300 February override.

Create these rows in this order (income_from ascending — the lookup picks the first match):

2.1 Maharashtra — ₹0 slab (income up to ₹7,500)
json
POST /payroll/statutory-slabs/create/
{
  "slab_type": "PT",
  "state": 19,
  "income_from": "0.00",
  "income_to": "7500.00",
  "fixed_amount": "0.00",
  "rate_percentage": null,
  "is_february_override": false,
  "additional_amount": "0.00",
  "frequency": "MONTHLY",
  "effective_from": "2023-04-01",
  "effective_to": null,
  "notes": "Maharashtra PT — exempt up to 7500"
}
2.2 Maharashtra — ₹175 slab (₹7,501 to ₹10,000)

2.4 Maharashtra — February ₹300 override (above ₹10,000)
json
POST /payroll/statutory-slabs/create/
{
  "slab_type": "PT",
  "state": 19,
  "income_from": "10000.01",
  "income_to": null,
  "fixed_amount": "0.00",
  "rate_percentage": null,
  "is_february_override": true,
  "additional_amount": "100.00",
  "frequency": "MONTHLY",
  "effective_from": "2023-04-01",
  "effective_to": null,
  "notes": "Maharashtra PT — February +100 override (base 200 + 100 = 300)"
}

How the Feb override works in your code: get_pt_slab_amount finds the normal slab (₹200 for income > ₹10,000), then looks for a Feb override slab with the same income band, and adds the additional_amount to the normal slab's fixed_amount. So ₹200 (base) + ₹100 (additional) = ₹300 in February. This matches Maharashtra's actual rule.

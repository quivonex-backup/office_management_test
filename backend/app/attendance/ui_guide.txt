================================================================================
ATTENDANCE (settings, shifts, punch, records, corrections) — UI GUIDE (for the UI designer / frontend)
================================================================================
Who      : Employees (punch, own records, corrections); attendance managers / HR / owner (setup, org records, review)
Apps     : Employee mobile app (punch with selfie + GPS); web panel (admin side)
Details  : request/response fields are in admin.txt, employee.txt
Tags     : urls.py marks each endpoint  #SU super admin, #A admin side,
           #E employee, perm: <code> = permission the caller needs.
           Show admin screens only when my-profile data.permissions contains
           the code (organization owner has every code).

SCREENS (employee)
1. Punch                     punch/  (multipart: selfie, latitude, longitude, gps_accuracy)
   - One button; the server decides CHECK_IN / CHECK_OUT. Show the backend message
     on failure (face mismatch, outside location, GPS accuracy, shift ended).
   - Remote employees (my-profile attendance_location_exempt = true) can punch
     from anywhere; still send GPS when available. Admin attendance views can
     show a "Remote" badge when verification_details.location_exempt is true.
2. My attendance             my-attendance/ (month view), detail/
3. My shifts                 my-shifts/ (current_shift + history)
4. Correction request        my-attendance/correct/ or corrections/create/, list in corrections/list/
5. Face registration check   face-recognition/

SCREENS (admin side)
1. Attendance settings       settings/   photo/location required, radius, GPS accuracy,
                             grace minutes, half-day thresholds, overtime rules, auto absent
2. Shifts                    shifts/list|create|update|deactivate/
3. Shift assignments         shift-assignments/* incl. bulk-assign, bulk-assign-pattern, bulk-close
4. Attendance register       list/  filters employee_id, status, work_date / from_date-to_date
   - Day detail opens from the row (punches with selfie, distance, face score are inside the row).
5. Missing attendance        bulk-mark-absent/  (dates up to yesterday)
6. Correction review         corrections/list/, corrections/review/

PROCESS
  Settings -> shifts -> assign shifts (and calendar weekly offs) -> employees punch
  -> managers review PENDING_REVIEW / corrections -> mark missing days absent
  before payroll.

ACCESS (batch 2)
  - Register (list/) and corrections: show a Mine / My team / Everyone switch,
    only with the options the user has (attendance.view_self / view_team /
    view_all). Send "scope"; read "scope_applied".
  - Review button only with attendance.approve_correction. The server refuses
    own requests and people outside the team: show its message.
  - Setup screens (settings, shifts, assignments): settings.manage.
    Shift lists are readable with any attendance admin code.
  - Mark absent: attendance.correct.
  - Branch geofence: an employee in a branch with a map pin punches against
    the branch; the punch detail shows verification_details.branch.

KIOSK (batch 12)
  Admin screen "Attendance devices" (attendance.device_manage):
    table name / code / password (show + copy) / branch / logged in / last seen;
    actions Edit, Reset password (confirm: "the tablet will be logged out"),
    Deactivate / Reactivate.
  Kiosk app (tablet):
    1. Login screen: device code + password -> kiosk/login/. Keep the token
       (secure storage). Show organization logo + name and device name.
    2. Home: two big buttons Check in / Check out. Logout icon at the top
       (asks for confirmation, then just deletes the token; no API).
    3. Scan the employee QR (holds the employee code) or type the code.
    4. Front camera selfie when photo_required; send the tablet's GPS when
       location_required (fixed tablet: ask once for location permission).
    5. kiosk/punch/ -> show employee photo + name + "Checked in 09:05"
       for 3 seconds, then back to Home. On 400/404 show the message.
    On 401 go back to the Login screen.
  Employee QR: build it in the employee app / ID card from employee_code;
  no API is needed.

================================================================================
ORGANIZATION STRUCTURE + ACCESS (BATCH 1) — API REFERENCE FOR FRONTEND
================================================================================

Method   : All endpoints are POST
Auth     : Bearer token
Envelope : { "status": true|false, "message": "...", "data": ...?, "errors": {...}? }
Org      : single-org users omit organization_id; multi-org users send it.
403 body : { "status": false, "message": "You do not have permission to perform this action." }

CONCEPTS
  accounts.Role   (unchanged)  Admin = organization owner, Employee = everyone else.
  Access role     (new, per organization) e.g. HR Manager, HR Executive,
                  Department Manager, Payroll Manager. Holds permission codes.
                  One access role per employee (Employee.access_role).
  Branch          (new, per organization) an office of the same company.
                  Has its own GPS point + radius (used by attendance from batch 2).
  Department / Designation (new, per organization) dropdown masters.

  Who has which permission:
    - Organization owner        -> every code.
    - Employee with access role -> the role's codes + self-service codes.
    - Employee without role     -> self-service codes only:
                                   dashboard.view, attendance.view_self,
                                   leave.apply, payroll.view_self
    - Super admin               -> nothing inside organizations.

  Build the menu from my-profile data.permissions (one menu for everyone).

  New organizations get the 4 default access roles automatically.
  Existing organizations got them from migration accounts 0009.

1. POST /accounts/my-profile/   (existing; fields ADDED, nothing removed)
--------------------------------------------------------------------------------
data = existing user fields (id, username, email, mobile, role, role_details, ...) +
{
  "account_role": "Employee",                  // accounts.Role name or null
  "is_org_owner": false,
  "organization": { "id": 3, "name": "Quivonex" },          // null if none
  "employee": {                                              // null if no Employee row
    "id": 12, "employee_code": "EMP-000012", "full_name": "Priya Shah",
    "branch":      { "id": 1, "name": "Pune HQ" },           // or null
    "department":  { "id": 4, "name": "Engineering" },       // id null = legacy text only
    "designation": { "id": 7, "name": "Software Engineer" },
    "reports_to":  { "id": 9, "full_name": "Vikram Rao" }    // or null
  },
  "access_role": { "id": 2, "name": "HR Executive" },        // or null
  "permissions": ["applicant.create", "applicant.view", "dashboard.view", ...]
}

--------------------------------------------------------------------------------
2. BRANCH   (list: any member; create/update/deactivate: org.manage)
--------------------------------------------------------------------------------
POST /accounts/branch/list/        { "search"?: "pune", "is_active"?: true }
POST /accounts/branch/create/      { "name": "Pune HQ", "code"?: "PUN", "address"?: "...",
                                     "city"?: "Pune", "state_id"?: 21,
                                     "latitude"?: 18.5204, "longitude"?: 73.8567,
                                     "allowed_radius_meters"?: 150 }
POST /accounts/branch/update/      { "branch_id": 1, ...only changed fields }
POST /accounts/branch/deactivate/  { "branch_id": 1 }

Branch object:
{ "id": 1, "name": "Pune HQ", "code": "PUN", "address": null, "city": "Pune",
  "state_id": 21, "state_name": "Maharashtra", "latitude": "18.520400",
  "longitude": "73.856700", "allowed_radius_meters": 150, "is_active": true,
  "employee_count": 14, "created_at": "...", "updated_at": "..." }

Rules: name unique per organization (case-insensitive); latitude and longitude
together or neither; allowed_radius_meters null = attendance settings radius;
deactivate refused while active employees are assigned
("This branch is assigned to N active employee(s). Move them first.").

--------------------------------------------------------------------------------
3. DEPARTMENT / DESIGNATION   (list: any member; others: org.manage)
--------------------------------------------------------------------------------
POST /employees/department/list/        { "search"?: "", "is_active"?: true }
POST /employees/department/create/      { "name": "Engineering", "code"?: "ENG" }
POST /employees/department/update/      { "department_id": 4, "name"?: "...", "code"?: "..." }
POST /employees/department/deactivate/  { "department_id": 4 }

POST /employees/designation/list/       { "search"?: "", "is_active"?: true }
POST /employees/designation/create/     { "name": "Software Engineer" }
POST /employees/designation/update/     { "designation_id": 7, "name": "..." }
POST /employees/designation/deactivate/ { "designation_id": 7 }

Department: { "id", "name", "code", "is_active", "employee_count", "created_at", "updated_at" }
Designation: { "id", "name", "is_active", "employee_count", "created_at", "updated_at" }
Renaming updates the text field on linked employees. Deactivate refused while in use.

--------------------------------------------------------------------------------
4. PERMISSIONS + ACCESS ROLES   (access.manage)
--------------------------------------------------------------------------------
POST /accounts/permission/list/      {}
  data: [ { "code": "applicant.create", "group": "Applicants", "label": "Create applicant" }, ... ]
  Use group for the matrix sections.

POST /accounts/access-role/list/     { "is_active"?: true }
  data: [ { "id": 2, "name": "HR Executive", "description": "...", "is_active": true,
            "permission_codes": ["applicant.create", ...], "employee_count": 3,
            "created_at": "...", "updated_at": "..." } ]

POST /accounts/access-role/create/   { "name": "Team Lead", "description"?: "...",
                                       "permission_codes": ["leave.view_team", "leave.approve"] }
POST /accounts/access-role/update/   { "access_role_id": 5, "name"?: "...", "description"?: "...",
                                       "permission_codes"?: [...] }   // full replacement when sent
POST /accounts/access-role/deactivate/ { "access_role_id": 5 }        // refused while assigned

Unknown permission code -> 400 with errors.permission_codes.

--------------------------------------------------------------------------------
5. EMPLOYEES (existing endpoints; fields ADDED)
--------------------------------------------------------------------------------
Permissions now enforced:
  /employees/create/        employee.update  (+ employee.create_user when create_user=true)
  /employees/create-user/   employee.create_user
  /employees/update/        employee.update
  /employees/deactivate/    employee.update
  (list/detail scope comes in batch 2)

create / update accept (all optional; blank or null clears the link):
  "branch_id", "department_id", "designation_id",
  "access_role_id"  (also needs access.manage),
  "reports_to_id"   (same organization; loops rejected)
  Old clients may keep sending "department"/"designation" text: when it matches
  a master name the link is set; sending department_id overwrites the text.

list / detail / my-profile (employees app) rows gain:
  "branch":          { "id", "name" } | null
  "department_ref":  { "id", "name" } | null
  "designation_ref": { "id", "name" } | null
  "access_role":     { "id", "name" } | null
  "reports_to":      { "id", "employee_code", "full_name" } | null
list filters added: branch_id, department_id, designation_id, access_role_id, reports_to_id

Errors (400): errors.<field> e.g.
  { "branch_id": ["Active branch not found in this organization."] }
  { "access_role_id": ["You do not have permission to assign access roles."] }
  { "reports_to_id": ["This reporting manager would create a reporting loop."] }

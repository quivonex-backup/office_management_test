================================================================================
REPORTS APP — ADMIN API REFERENCE (dashboard + reports)
================================================================================

Base URL   : /reports/
Method     : All endpoints are POST
Auth       : Bearer token
Envelope   : { "status": true|false, "message": "...", "data": {...}?, "errors": {...}? }
Org        : single-org users omit organization_id; multi-org users send it.
Models     : none. The app only reads data from the other apps.
Permissions: existing view codes only (no new codes). Whoever may view a report
             may also download it. *_team codes get only their reportees
             (reports_to tree); *_all codes get everyone.

--------------------------------------------------------------------------------
1. POST /reports/dashboard/          everyone (owner + employees)
--------------------------------------------------------------------------------
{ "month"?: "2026-11",                  month for the month widgets (default: now)
  "widgets"?: ["headcount", "celebrations"] }   only these (lazy loading)
200 {
  "generated_at": "...", "month": "2026-11",
  "available_widgets": ["my_today", ...],    what this user may see (draw these)
  "widgets": { "<key>": {...}, ... },
  "failed_widgets": []                       a widget that errored (logged), others still load
}
Unknown widget name -> 400. A widget the user may not see is simply left out.

2. POST /reports/list/               everyone
--------------------------------------------------------------------------------
{} -> { "reports": [ { "key": "attendance", "title": "Attendance", "group": "People",
                       "url": "/reports/attendance/", "formats": ["json", "xlsx"],
                       "filters": [ {"key": "from_date", "type": "date", "default": "..."},
                                    {"key": "branch_id", "type": "branch"}, ... ] } ],
        "organization_features": {has_branches, has_departments, has_designations, payslip_mode} }
Only reports the caller may open; only filters that apply to the organization
(no branch filter without branches, no OT filter when overtime is off, ...).
filter types: date, month, text, bool, choice (+ options), employee, department,
branch, designation, leave_type, payroll_run (ids from the usual list APIs).

--------------------------------------------------------------------------------
3. REPORTS — common request / response
--------------------------------------------------------------------------------
Request: { "from_date"?: "2026-11-01", "to_date"?: "2026-11-30",   default = this month,
           max range 366 days
           "employee_id"?, "department_id"?, "branch_id"?, "designation_id"?, "search"?,
           ...report filters...,
           "format"?: "json" (default) | "xlsx",
           "page"?: 1, "page_size"?: 50 (max 500; json only) }
JSON 200 data:
{ "report": "attendance", "title": "Attendance summary 01 Nov 2026 - 30 Nov 2026",
  "filters": {... what was applied, incl. "scope": "all" | "team"},
  "columns": [ {"key": "present", "label": "Present", "type": "number"}, ... ],
  "rows": [ {...one object per row, keys = columns...} ],
  "totals": { "present": 812, ... },     numeric columns
  "chart": {chart shape},
  "summary"?: {...},                     some reports
  "pagination": {page, page_size, total_rows, total_pages} }
column types: text | number | money | date | time | bool
xlsx: file download (Content-Disposition attachment) with ALL rows, same columns,
title + filters + generated time on top, totals row, header filter + frozen header.

COLUMNS FOLLOW THE ORGANIZATION
  - Department / Branch / Remote only when the organization has them.
  - Payroll SIMPLE mode: no PF / ESI / PT / LWF / employer columns; FULL: only the
    schemes switched on; VPF only with contribution type VPF; late deduction only
    when enabled; OT only when overtime is on. A column whose setting is off still
    appears when the data has values (e.g. an older run).
  - Columns marked "when used" appear only if some row has a value.
  - Filters that do not apply (branch_id without branches) are ignored.

Errors: 400 bad filter / dates, 403 no permission ("You do not have permission to
view this report."), 404 (payroll: no run).

4. POST /reports/attendance/         attendance.view_all | attendance.view_team
--------------------------------------------------------------------------------
Filters: view "summary" (default, one row per employee) | "daily" (one row per day)
         status PRESENT | HALF_DAY | ABSENT | ON_LEAVE | INCOMPLETE | PENDING_REVIEW |
                HOLIDAY | WEEKLY_OFF
           daily: rows with that status;  summary: employees with at least one such day
                  (ABSENT / HALF_DAY / ON_LEAVE)
         late_only, early_only, overtime_only (true)
  Absent report        { "view": "daily", "status": "ABSENT" }
  Late comers (month)  { "late_only": true }
Summary columns: employee_code, name, department, branch, present, half_days, absent,
  on_leave, incomplete (when used), late_days, late_minutes, early_minutes,
  overtime_hours, worked_hours, remote
Daily columns: work_date, employee_code, name, department, branch, shift, check_in,
  check_out, status, late_minutes, early_minutes, overtime_minutes, worked_hours, remote
Summary lists every active employee in scope (also with no records). Days without
any attendance record are not "absent" rows (absent = records marked ABSENT).
Chart: summary bar (present / half / absent / leave); daily line (records, late).

--------------------------------------------------------------------------------
5. POST /reports/leave/              leave.view_all | leave.view_team
--------------------------------------------------------------------------------
Filters: view "taken" (default) | "balance", leave_type_id,
         status PENDING | APPROVED | REJECTED | CANCELLED
taken: applications overlapping the period (full application days)
  columns: employee_code, name, department, branch, leave_type, paid, from, to, days,
           status, applied_on, reviewed_by, reason
  summary: {applications, approved_days, pending}; chart: approved days per type
balance: leave year = year of to_date; one row per active employee; per leave type
  "<CODE>_allocated", "<CODE>_used", "<CODE>_pending" (when used), "<CODE>_available"

--------------------------------------------------------------------------------
6. POST /reports/payroll/            payroll.view_all
--------------------------------------------------------------------------------
Filters: payroll_run_id | month ("2026-11" = the run that ends in that month);
         default = latest run. payment_status UNPAID | PARTIALLY_PAID | PAID,
         requires_review (true). No date range.
Columns: employee_code, name, department, branch, monthly_salary, paid_days, absent_days,
  half_days, unpaid_leave_days, late_minutes, overtime_hours, overtime_amount, gross, lop,
  late_deduction, pf, vpf, esi, pt, lwf, tds, other_deductions, total_deductions, net,
  pf_employer (incl. EPS + EDLI), esi_employer, lwf_employer, employer_cost,
  payment_status, paid_amount, requires_review   (see "columns follow the organization")
filters also has period_start, period_end, run_status. Extra: "runs" (last 24 runs
for the run dropdown), "payslip_mode". Chart: gross / deductions / net of the last 6 runs.
404 "No payroll runs yet." / "No payroll run ends in <month>."

--------------------------------------------------------------------------------
7. POST /reports/recruitment/        applicant.view
--------------------------------------------------------------------------------
Period = applied_on. Filters: view "applicants" (default) | "funnel", stage, status,
  source, designation_id, department_id, assigned_to_id, search
Visibility: applicant.create / update / status_update / verification.update /
  onboarding.complete see all; applicant.view alone sees applicants assigned to them
  or that they interview (same as the recruitment app).
applicants columns: applicant_code, name, applied_on, position, department, source,
  assigned_to, stage, status, interviews_done, last_interview_result, offer_status,
  offered_ctc, joining_date, days_in_pipeline; chart: applications per week
funnel rows: stage, current (now in stage), reached (got at least this far),
  percent_of_applied; summary {applied, offers_sent, offers_accepted, offers_declined,
  hired, average_days_to_hire}

--------------------------------------------------------------------------------
8. POST /reports/employees/          employee.view_all | employee.view_team
--------------------------------------------------------------------------------
Filters: view "headcount" (default; active employees, dates ignored) | "joiners"
  (joining_date in period) | "exits" (resignation_date in period),
  employment_status ACTIVE | INACTIVE | ON_LEAVE | RESIGNED | TERMINATED,
  access_role_id, remote_only (only when the organization has remote employees)
Columns: employee_code, name, department, designation, branch, joining_date, exit_date,
  status, active (joiners / exits), reports_to, mobile, email (personal), access_role, remote
Chart: headcount by department (designation when no departments); joiners vs exits per month.
summary: {employees}

--------------------------------------------------------------------------------
9. POST /reports/expenses/           reimbursement.review | reimbursement.pay | expense.manage
--------------------------------------------------------------------------------
view "reimbursements" (needs reimbursement.review / pay) | "company" (needs expense.manage);
default = reimbursements when allowed, else company. Other view -> 403.
Common filters: from_date / to_date (expense date), category (food, travel, utilities,
  rent, software, cloud, equipment, office, maintenance, telephone, marketing,
  professional_services, other), project_id, search
reimbursements: + status PENDING | APPROVED | REJECTED | PAID | CANCELLED, employee /
  department filters. Columns: number, expense_date, employee_code, name, department,
  category, title, project, amount, status, reviewed_by, payment_date.
  summary {claims, amount_by_status}
company: one-off expenses + recurring expense entries (date = entry due date, else the
  1st of its month) in the period; + payment_status paid | unpaid, vendor_id.
  Columns: date, number, source (One-off / Recurring (Monthly)), category, title, vendor,
  project, amount, due_date, payment_status, payment_date. summary {entries, unpaid}
Chart: amount per category. Totals: amount.

--------------------------------------------------------------------------------
10. POST /reports/receivables/       payment.manage
--------------------------------------------------------------------------------
Rows = project payment rows (advance / installments), cancelled excluded, due in the period.
Filters: client_id, project_id, status PENDING | PARTIALLY_PAID | PAID | OVERDUE,
  payment_type ADVANCE | INSTALLMENT, overdue_only (everything overdue today; dates
  ignored), include_undated (rows without a due date too), search (project / client / title)
Columns: client, project, project_code, payment_type, installment, title, due_date, amount,
  paid (received), outstanding, status, days_overdue, last_payment_date
summary: {collected_in_period (successful transactions dated in the period),
  overdue_total, ageing_days {"0-30", "31-60", "61-90", "90+"}}
Chart: overdue outstanding by age bucket. Totals: amount, paid, outstanding.

--------------------------------------------------------------------------------
11. POST /reports/projects/          project.manage
--------------------------------------------------------------------------------
Active projects (snapshot); the period only drives "done in period" (tasks completed then).
Filters: view "projects" (default) | "assignees", project_status new | in_progress |
  testing | completed | on_hold | cancelled, project_id, client_id, assignee_id,
  overdue_only, search
projects columns: project_code, project, client, status, priority, heads (project heads),
  start_date, deadline, late (past deadline, not completed), total_tasks, done_tasks,
  open_tasks, overdue_tasks, done_in_period, percent_complete, total_cost (project value)
assignees columns: employee_code, name, projects, total_tasks, open_tasks, overdue_tasks,
  done_in_period (sorted by most overdue)
Chart: done vs open per project / open vs overdue per assignee (top 15).

--------------------------------------------------------------------------------
12. POST /reports/helpdesk/          ticket.manage | ticket.handle
--------------------------------------------------------------------------------
Tickets raised in the period. ticket.manage = all; ticket.handle = own department's
categories + tickets assigned to them (same as the helpdesk queue).
Filters: view "tickets" (default) | "summary", category_id, status, priority,
  assigned_to_id, unassigned_only, search
tickets columns: ticket_code, raised_on, raised_by, department, category, subject,
  priority, status, assigned_to, resolved_on, resolution_hours, open_days (still open),
  reopened; summary {tickets, open, average_resolution_hours, reopened};
  chart raised vs resolved per day
summary view (per category): raised, resolved (resolved in period), open_now (all open,
  any date), average_resolution_hours, oldest_open_days; chart raised vs resolved.


================================================================================
SECTION — ASSETS + VISITORS REPORTS (batch 18)
================================================================================
Same request / response shape as every report (columns, rows, totals, chart,
summary, pagination; "format": "xlsx" downloads). Both appear in reports/list/
(group "Office") for callers with the code.

POST /reports/assets/        perm: asset.view | asset.manage
  { "view": "register" | "holders" | "history",       // default register
    "category_id"?, "branch_id"? (only with branches), "employee_id"?,
    "status"? (register: AVAILABLE | ASSIGNED | IN_REPAIR | RETIRED | LOST),
    "warranty_expiring_days"? (register: warranty ends within N days),
    "from_date"?, "to_date"? (history only; default this month), "search"? }
  register: active assets today: asset, name, category, brand, model, serial,
            branch, status, holder, assigned on, purchase date / cost,
            warranty until / expired. totals.purchase_cost; chart bar by
            status; summary {assets, available, assigned, in_repair, retired,
            lost, warranty_expired}.
  holders:  employees holding assets now: emp code, employee, department,
            assets held, purchase value, asset list. totals assets_held / value.
  history:  assignments issued or returned in the period: asset, employee,
            issued on / condition, returned on / condition, days held.
            summary {assignments, issued, returned, still_held}.
  400 bad view / status / warranty_expiring_days.

POST /reports/visitors/      perm: visitor.manage
  { "from_date"?, "to_date"?,                         // default this month (by check-in)
    "view": "visits" | "summary",                     // default visits
    "group_by": "host" | "purpose" | "day",           // summary, default host
    "purpose"?, "host_id"?, "branch_id"?, "still_inside"?: true, "search"? }
  visits:  visit, date, in, out, stay (min), visitor, mobile, company, people,
           purpose, host, host department, branch, badge, vehicle, still
           inside. totals.visitor_count; chart line per day; summary {visits,
           visitors, still_inside, average_minutes}.
  summary: one row per host ("No host" too) / purpose / day (every day in the
           range): visits, visitors, average stay. totals visits / visitors.
  400 bad view / group_by / purpose.
Deactivated assets and visits are excluded. The older list exports
(visitors/visit/list/ and assets/asset/list/ with "format": "xlsx") still work.

9. What you do not need
No new models in attendance — only 3 function edits.

No new models in accounts or employees.

No FK from attendance to leave at the DB level.

No EmployeeWeeklyOffOverride unless a customer asks.

No Notification model in this round (defer to Sprint 5).

No multi-step approval framework — single reviewed_by FK is enough for the 24+5 use case.

No tax/PF/ESI in payroll v1 — start with per_day_rate × present + half + paid_leave + overtime − absent.

The four things this design guarantees:

No circular imports — the one two-way edge (attendance ↔ leave) is broken by a lazy import.

No schema changes to existing models — attendance gets zero new columns.

No change to the punch path — process_attendance_punch, face verification, location verification all untouched.

Payroll reads only AttendanceRecord.status — approve a leave, attendance flips to ON_LEAVE, payslip pays. Reject, attendance stays ABSENT, payslip deducts. One-way data flow.
